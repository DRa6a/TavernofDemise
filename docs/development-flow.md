## 二、开发阶段详解

### 阶段一：核心引擎落地（M1）

**目标**：让 `core/` 目录能够独立运行一局游戏。

**任务清单**：

1. **模型层**
   - 定义 `Card`、`Player`、`DivineDice`、`GameState`、`GameEvent` 类型
   - 在 `utils/constants.ts` 中固化常量（牌数、生肖、神兽、回合类型）
2. **牌堆与洗牌**
   - 实现 `DeckBuilder.buildStandardDeck()`
   - 实现 `Shuffler.shuffle(deck, seed)`
3. **规则引擎**
   - 实现真假判定
   - 实现出牌合法性校验
   - 实现质疑胜负判定
   - 实现神兽判决
4. **状态机**
   - 实现 `RoundManager`，按顺序推进选举/抽牌/真牌/出牌/开牌/生死
   - 处理玩家出局、上下家跳过、胜利判定
5. **AI 基础策略**
   - 实现随机策略，保证游戏能自动跑通
6. **事件系统**
   - 定义 `GameEvent` 联合类型
   - 引擎每步操作产生事件并写入 `history`
7. **测试**
   - 为 DeckBuilder、RuleEngine、RoundManager 编写单元测试

**验收标准**：

- 通过一段测试脚本可运行 100 局随机对战不报错
- 可输出每局胜负与关键事件日志

---

### 阶段二：UI 与交互落地（M2）

**目标**：玩家能在网页上完成一局游戏。

**任务清单**：

1. **Zustand Store**
   - 创建 `gameStore`，持有 `GameState`
   - 暴露 `startGame`、`playCards`、`challenge`、`pass`、`nextStep` 等 action
   - 引擎事件通过 Store 同步到 UI
2. **基础组件**
   - `Card`：牌面/牌背渲染，色语、肖子、道牌标识
   - `Dice`：六面神兽骰子，支持旋转动画
   - `PlayerSeat`：玩家座位，显示手牌数、生死状态
   - `ActionBar`：出牌/质疑/跳过按钮
3. **全屏场景**
   - `MainMenuScreen`：开始游戏、选择人数
   - `GameScreen`：对局主界面
   - `ResultScreen`：结算界面
4. **人机流程**
   - AI 回合自动触发（使用 `setTimeout` 模拟思考）
   - 人类玩家回合高亮提示
5. **规则反馈**
   - 质疑翻开动画
   - 生死结算提示
   - 错误操作 Toast（如出牌数超限）

**验收标准**：

- 在桌面浏览器可完成一局 2~6 人对战
- 所有规则边界（强制质疑、出完观战、死亡继承）表现正确

---

### 阶段三：移动端适配与体验打磨（M3）

**目标**：手机竖屏体验流畅，视觉与动效符合“终焉酒馆”氛围。

**任务清单**：

1. **响应式布局**
   - 竖屏扇形座位，横屏环形/桌面布局
   - 底部固定操作区，避免误触
2. **视觉主题**
   - 暗色纸质感背景
   - 牌相色语、神兽图标、血墨动效
   - 自定义字体与文字特效
3. **动画与反馈**
   - 卡牌飞入/飞出、翻开
   - 骰子旋转后落定
   - 死亡/胜利全屏特效
   - 触感/震动反馈（可选）
4. **AI 升级**
   - 简单/普通/困难三档难度
   - 优化出牌与质疑决策，避免明显弱智或作弊感
5. **音效与音乐（可选）**
   - 出牌、质疑、骰子、胜利/失败音效
   - 背景音乐开关

**验收标准**：

- 在 iOS Safari / Android Chrome 上运行流畅
- 操作热区符合移动端规范
- 一局游戏平均时长 5~10 分钟

---

### 阶段四：扩展与联机准备（M4）

**目标**：架构层面支持 Mod 与网络，代码文档化。

**任务清单**：

1. **Mod 系统**
   - 定义 `GameMod` 接口
   - 实现 `ModLoader` 与示例 Mod（如“双倍道牌”）
   - UI 增加 Mod 管理界面
2. **网络抽象层**
   - 完善 `NetworkTransport` 接口
   - 实现本地空实现 `LocalTransport`
   - 编写联机状态同步文档
3. **代码文档**
   - 为公共接口补充 JSDoc
   - 编写 `docs/api.md`（可选）
4. **构建优化**
   - 配置 Vite 打包拆分
   - 静态资源压缩
   - PWA 基础配置（可选）

**验收标准**：

- 可在不修改核心代码的情况下加载示例 Mod
- 可替换 `NetworkTransport` 实现而不影响 UI

## 三、代码规范

### 3.1 命名约定

| 类型 | 约定 | 示例 |
|------|------|------|
| 目录/文件 | 小写 + 连字符 | `round-manager.ts` |
| 类型/接口 | PascalCase | `GameState`, `RuleEngine` |
| 函数/变量 | camelCase | `resolveChallenge`, `activePlayerId` |
| 常量 | SCREAMING_SNAKE_CASE | `TOTAL_CARDS`, `HAND_SIZE` |
| React 组件 | PascalCase | `GameScreen`, `CardView` |
| CSS 变量 | `--kebab-case` | `--color-tian`, `--spacing-md` |

### 3.2 模块边界

- `core/` 不得引用 `react`、`zustand`、DOM API
- `ui/` 可以依赖 `core/` 和 `store/`
- `store/` 作为 `core/` 与 `ui/` 之间的薄层
- 通用工具放 `utils/`

### 3.3 状态不可变性

- 所有状态更新使用展开运算符或 immer
- 禁止在组件中直接修改 `gameState.players[0].hand`

### 3.4 注释原则

- 复杂规则必须注释规则来源（规则文档章节）
- 公共接口使用 JSDoc
- 不写无意义注释（如 `// 初始化`）

## 四、测试策略

### 4.1 测试分层

| 层级 | 范围 | 工具 | 目标 |
|------|------|------|------|
| 单元测试 | `core/` 中的纯函数与类 | Vitest | 覆盖率 ≥ 70% |
| 集成测试 | 一局完整游戏流程 | Vitest | 覆盖主要胜利路径 |
| 组件测试 | React 组件交互 | React Testing Library | 覆盖玩家输入反馈 |
| 手动测试 | 移动端真机 | 浏览器 DevTools + 真机 | 发现布局与性能问题 |

### 4.2 关键测试用例

- 标准牌堆生成 42 张，天/地/人各 12 张，道 6 张
- 真牌回合随机产出“天/地/人”之一
- 出牌 1~3 张，超过 3 张非法
- 假牌判定：含非真牌且非道牌即假
- 质疑成功/失败后正确进入生死回合
- 天龙必死，非天龙存活且该面出局
- 玩家死亡后上下家正确连接
- 仅剩一人时进入 GAME_OVER

## 五、构建与发布

### 5.1 开发命令

```bash
npm install      # 安装依赖
npm run dev      # 启动开发服务器
npm run build    # 生产构建
npm run preview  # 预览生产构建
npm run test     # 运行测试（配置后）
```

### 5.2 构建输出

- Vite 默认输出到 `dist/`
- 静态资源部署到任意静态服务器（Nginx、GitHub Pages、Vercel 等）

### 5.3 部署建议

- 使用 HTTPS（WebRTC/音频需要）
- 配置 `viewport` 与 `theme-color` meta 标签
- 添加 `manifest.json` 支持 PWA 添加桌面

## 六、版本与分支策略

- `main`：始终可构建，保存最新稳定 Demo
